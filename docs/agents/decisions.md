## D001 — 平台、技术栈与分层

**依据：**原 MVP 与用户给定约束明确选择 Windows x64、.NET 10、Avalonia、CommunityToolkit.Mvvm 和 Rider。目标是单媒体字幕工具，不承担跨平台或服务部署。

**决定：**保留 Core / Infrastructure / Desktop 分层，JSON 配置与缓存，Process 调用 FFmpeg。正式发行仅 `win-x64`；不采用 Electron、WebView、独立 Web 服务、数据库或插件框架。

**实施证据与影响：**桌面固定 Avalonia 11.3.12 的 Win32 + Skia + Fluent 包。原 Avalonia.Desktop 元包引入 Linux D-Bus 依赖并出现 NU1903，改为直接引用 Windows 所需包，未抑制审计。Core/Infrastructure 的 `net10.0` 用于降低耦合，不是跨平台支持；原生复制与发行仅保留 win-x64。依赖升级必须重新核验，不能按 skill 的版本自动迁移到 Avalonia 12。

## D002 — 本地模型与 Vulkan

**依据：**用户唯一指定腾讯官方 `Hy-MT2-1.8B-Q4_K_M.gguf`、LLamaSharp 和进程内 Vulkan；明确禁止外部模型服务、CLI、CUDA 和 CPU-only 替代。

**决定：**校验固定文件名和 SHA-256，使用 LLamaSharp 与官方 Windows Vulkan 原生包同版本 0.27.0。禁止自动后端回退；实际模块、设备、非零 GPU layer offload 和生成共同作为验证依据。模型权重复用，生成使用独立上下文及原生 chat template，检查 EOS、预算、取消与释放。

**证据与影响：**历史真实运行在 RTX 4070 Laptop GPU 上达到 33/33 层卸载并完成 10 条短句及取消/恢复检查，模型架构为 `hunyuan-dense`。Vulkan 包传递依赖 CPU 运算 DLL，模型也存在 CPU_Mapped 缓冲区；这不是 CPU-only 回退，也不能宣称全部算子/数据在 GPU。保留必要依赖，不为消除 CPU 文件名而破坏原生运行。新版本验收不能沿用旧 GPU 证据。

## D003 — 翻译协议、提示词与服务差异

**依据：**原 MVP 借鉴 SmartSub 的 ID 对齐和 AiNiee 的提示词/上下文构造思路。小型专用本地模型强制输出批量 JSON 可靠性较差。

**决定：**云端输出 `cueId -> translatedText` JSON，本地批次和并发固定 1，输出纯译文，由应用关联 ID。共享 `PromptBuilder`、`AlignmentValidator`、编排和缓存，模板按引擎保存；预设为本项目自编，不复制竞品实现。缺失条目有限补翻，严禁改变 ID、数量或时码，严禁原文冒充译文。

**服务选择：**兼容 API 与 DeepSeek 官方复用 transport，但官方思考映射单独处理，只读取最终 content。兼容性不是所有服务商的统一能力承诺。用户明确要求兼容路径使用 DS 简单验证，历史真实兼容验证仅覆盖该 DS 端点，未独立验证其他提供商。DeepSeek 参数的当前实现见 `CloudTranslationOptions`，上游 API 变化时重新查证官方资料。

**影响：**高级 JSON 受校验，不能覆盖受控字段或携带凭据；提示词自由编辑不能取消输出协议和对齐校验。术语库、角色管理和复杂可见思考过程不随这些借鉴加入范围。

## D004 — 缓存、恢复与费用

**依据：**ASR 和翻译都是可能计费的操作，修改目标语言或模型不能重复支付已有有效识别结果。取消/失败应尽量保留成功部分。

**决定：**输入、准备、VAD、ASR 和翻译身份分层；JSON 原子写入，作业互斥来自文件句柄。成功结果独立保存；网络/限流等错误有限退避，认证/参数错误不盲目重试。定向重翻先失效所选 ID 的旧缓存，失败后不能恢复旧译文冒充新结果。

**影响：**缓存键不含 Key；迁移配置或身份要评估复用与重新计费。固定并发波次保持上下文可重复，批次结果校验后逐步显示。完整译文不足时不导出完整 SRT。恢复和缓存命中不是新的真实服务或 GPU 验证。

## D005 — 界面指南与 Fluent

**依据：**用户要求先寻找可靠的 Avalonia 开发及 UI 设计 skill，再按指南实现。采用 [Wiesław Šoltés 的 Avalonia 指南](https://github.com/wieslawsoltes/development-plugin-for-avalonia)和 [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)。

**决定：**Avalonia 专项指南负责编译绑定、线程、布局、Fluent 和桌面资源；通用 UI skill 用于视觉层级、可访问性、进度与错误恢复。以当前已锁定版本核验 API，指南不能授权依赖升级或引入 ReactiveUI/Zafiro。

**影响：**通用设计系统搜索曾返回 Hero/Features/CTA 等营销网页结构，未直接采用。使用 Fluent 原生控件、Windows 字体、语义 tokens 和复用样式，不引入 CSS、WebView 或网页动效。最初的“左配置、右结果”布局已由后续用户确认的 D007 替代；此处不是恢复该布局的依据。

## D006 — 文案与状态整改

**依据：**用户指出“生成可复用的字幕”“禁止 Key”等提示不像正常软件。审查还发现默认云端显示本地状态、等待与失败混写、所有异常都声称能恢复、直接暴露异常类型等问题。

**决定：**日常界面描述用户动作、对象、真实状态和可执行建议；工程限制与验收术语进入开发文档，技术诊断进入安全日志。保留上传、计费、密钥保存范围和覆盖文件等有实际后果的信息。

**影响：**使用正常字幕序号，区分等待/处理中/失败/取消；按服务配置重置连接测试状态，区分认证、权限、限流、网络、模型与 GPU 错误。文案整改要同时修正状态和命令，不能只替换字符串。具体例子和自查要求见 [UI 与文案规约](ui-guidelines.md#产品语言)。

## D007 — 三步工作台与任务快照

**依据：**用户明确不喜欢左右分栏，要求设置与工作流分开、左侧图标切页，并选择分步方式，随后批准实施。

**决定：**左侧导航切换工作台、日志、设置；工作台为选择文件、翻译选项、生成字幕三步。页面共享长期 ViewModel，导航不改变任务生命周期。处理时锁定步骤和参数，允许查看其他页面。设置可从选项步骤直达对应分类，返回保留本次输入。

**状态决定：**设置草稿、已保存默认配置、本次选项和已启动任务快照分开。未保存编辑不进入媒体请求，已完成任务的预览、重翻、导出继续使用原快照。修改全局设置不会失效旧结果；重新开始处理才应用新配置。

**影响：**替代旧左右主分栏和“修改任何翻译设置即禁止导出/重翻”的逻辑。当前共享云端地址/模型/Key 的实现仍有明确限制，不等于已实现多服务配置档案，详见架构。自动化覆盖导航、步骤、快照和渐进结果；原生 GUI 人工验收另列。

## D008 — 仓库、资产与发行

**依据：**用户要求为首次正式提交清理大量 MVP 阶段文件，使项目具备正式仓库结构。

**决定：**保留三个生产项目、两套可维护测试、必要 Silero ONNX、复用发行检查及完整第三方许可；旧阶段文档、Spike、日志、媒体、付费缓存和发行包归档到仓库外。GGUF 本机保留且 Git 忽略，不随包发布。FFmpeg 由用户配置，Silero 随发行包。

**影响：**不恢复旧工程或命令作为后续生产依赖。依赖锁文件、版权许可与原生发布资产同步检查；不抑制 NuGet 审计。self-contained 本机启动已验证，但不等于独立无 SDK 机器验收。清理时项目自身许可证未指定，后续由维护者确认采用 MIT，见 D010。

## D009 — 持续文档体系

**依据：**用户在清理后要求补齐给后续 Agent 的规约、MVP 契约与历史决策，要求结构、索引及简明 AGENTS，并保留 UI 文案规则。

**决定：**产品、架构、Agent 指南、UI 规约、决策和验证状态统一放在 `docs/agents/`，以 `docs/agents/README.md` 为专用索引。通用开发命令和排障保留在 `docs/`，由 `docs/README.md` 引导。根目录 AGENTS 只列关键边界和阅读路线。提炼仍有效的内容，保留替代关系，不将旧阶段日志整份放回仓库。

**影响：**新任务不重新执行初始 Phase 0～3；按实际风险选择验证。历史真实结论、当前自动化和人工待验收分开。文档变化随行为/接口/依赖同步维护，证据位置不能变成对所有开发环境的本机路径要求。

## D010 — 项目 MIT 与第三方许可边界

**依据：**维护者在核对上游许可后批准项目采用 MIT，指定版权主体为 `2026 etnAtker`，并要求将改动 amend 到首次提交。

**决定：**自有代码与文档使用根目录 [LICENSE](../../LICENSE) 中的标准 MIT 文本；同步用户文档、Agent 指南及发行配置，发行检查要求项目许可证存在。第三方许可和版权保持完整，MIT 不重新授权第三方代码、模型或服务。

**影响：**Silero 随包保留 MIT 声明；指定官方 [Hy-MT2 GGUF](https://huggingface.co/tencent/Hy-MT2-1.8B-GGUF/blob/main/LICENSE.txt) 按 Apache-2.0 使用且不随包；FFmpeg 仍由用户提供。原生依赖的通用声明含 MPL、LGPL 和多重许可条款，适用组件、许可选择及源码获取义务须按实际 Windows 发行构建核对；项目采用 MIT 和资产检查通过均不能代替完整发行许可核验。借鉴思路不意味着获准复制其他项目的受限源码或提示词。

## D011 — 验证按需，提交不触发全量检查

**依据：**维护者明确要求去掉提交前强制测试的规约。

**决定：**提交和 amend 不自动触发还原、构建、测试或发行检查。按改动内容和风险选择必要验证，开发指南保留命令供需要时使用；不再要求每次代码交付至少跑完整还原、构建与测试。

**影响：**替代原开发规约中的固定验证门禁。已有验证结果仍按实际执行情况报告，未执行的检查如实说明；产品验收标准与真实/模拟证据边界不因取消提交门禁而改变。

## 后续决策记录格式

新增重要决策使用下一个稳定编号，说明日期、状态、触发问题、证据、批准的方案、影响和验证边界。替代旧决策时同时标明旧条目的状态与新编号。普通测试次数、一次性构建修复和逐轮聊天内容不新增决策；它们进入交付报告或相关验证记录。
