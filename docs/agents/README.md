# Agent 文档索引

Cuelify 的 Agent 专用资料统一保存在 `docs/agents/`，这里是后续开发与交接的入口。通用文档见[文档索引](../README.md)，用户安装和使用先看根目录 [README](../../README.md)。

## Agent 阅读顺序

1. 阅读根目录 [AGENTS.md](../../AGENTS.md)、[产品范围](product.md)和 [Agent 工作指南](agent-guide.md)，确认本次任务的范围与工作方式。
2. 阅读[当前架构](architecture.md)和[开发指南](../development.md)，定位现有实现与验证命令。
3. 改动界面时，必须阅读 [UI 与文案规约](ui-guidelines.md)。
4. 涉及技术选择、历史行为或验收结论时，查阅[决策记录](decisions.md)与[验证状态](status.md)。
5. 阅读目标模块源码及相应测试，再提出修改计划；不要只依据文档推断实现。

## 来源与维护原则

本体系由 2026-10-09 冻结的原 `MVP_SPEC.md`、原 `CODEX_EXECUTION.md`、历史技术决策、后续用户确认及当前代码整理而来。旧阶段材料已在仓库外归档；它们供追溯，不能直接作为当前操作指引。原始证据的位置见[验证状态](status.md#历史证据位置)。

后续用户明确批准的变化可以替代旧决策。例如，三步工作台已替代最初的左右分栏；任务快照已替代“修改全局设置就失效旧结果”的行为。冲突时先说明差异：产品范围约束应做什么，架构描述代码现在如何工作，验证状态说明哪些结论有证据。代码偏离批准的约束属于待修复问题，不能仅靠改文档将其合理化。

每条长期规则在对应文档维护，AGENTS 只保留关键要求和入口。不要重新引入逐轮聊天记录、Phase 清单、一次性 Spike 命令、测试产物或本机凭据路径；示例必须标明用途，历史验证不能写成新版本已验收。
