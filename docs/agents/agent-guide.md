# Agent 开发与交接指南

本文件保存详细开发规约。根目录 [AGENTS.md](../../AGENTS.md)保留核心要求，阅读入口和任务路由见[文档索引](README.md)。

## 开始任务

1. 先检查工作目录、Git 状态、相关文档、模块入口、引用与测试。识别用户现有改动，不能无关覆盖、回滚或清理。
2. 区分用户新需求、已经批准的决定和历史提案。查看[产品范围](product.md)、[决策记录](decisions.md)及[验证状态](status.md)，不要把旧 Phase 待办重新当作当前任务。
3. 阅读完整数据流，尤其是时间轴、缓存身份、任务快照和资源所有权。文档中的概念接口不能代替实际签名。
4. 缺少影响正确性的输入或发现真正的逻辑断层时，说明具体缺项并向用户澄清；其他不依赖缺项的工作可继续。常规实现细节由现有风格和已授权范围决定。
5. 编码前提交简短计划，列出目标、受影响文件、核心改动、影响面和验证方式，取得明确授权。已批准计划内持续实施，不为每个方法重复索取许可；范围或冻结决策变化时重新对齐。

面向用户的说明、提问、建议、交接和文档使用中文；代码标识符遵循现有 C# 命名。不要因为理解了需求就跳过上下文和计划，也不要将“建议考虑”写成用户已经批准。

## 实施原则

- 复用生产组件：`ICommandRunner`、识别/翻译编排、提示词与对齐、原子存储、设置校验和用户错误映射。不在 UI、脚本或测试里复制一套业务实现。
- 一次围绕一个逻辑范围交付，保持三层职责。没有当前需要，不建立插件框架、数据库、通用模型管理或新的服务进程。
- 共享类型、缓存身份、配置结构变化时检查所有引用，考虑旧 JSON 和付费缓存；不能默默丢弃成功结果来规避兼容问题。
- Avalonia 使用原生控件、XAML-first、`x:DataType` 编译绑定、CommunityToolkit.Mvvm 命令和既有资源。改 UI 前阅读 [UI 与文案规约](ui-guidelines.md)，不要把开发要求直接写进界面。
- 长操作不得阻塞 UI；集合更新回到 UI 线程。显式处理重复启动、取消、关闭、订阅解除及权重/上下文释放。
- 对依赖缺失、API 不兼容或环境限制报告真实证据，提出最小修复。测试替身用于隔离验证，不能硬编码到正式路径充当真实实现，也不能擅自换技术栈。
- 技术范围或关键行为变化，先说明问题、证据、替代方案和影响；用户决定后更新决策记录。记录日期、状态和替代关系，不留多份互相冲突的“当前方案”。

## 凭据与外部调用

真实服务调用以用户授权的服务、输入和请求范围为限，注意测试连接也可能计费。先用 fake HTTP 验证协议和错误分支，再用最小真实输入确认。用户已授权的同一工作不重复询问；不能把一次授权推导为后台反复调用或扩大请求量。

通过当前会话的安全来源读取 Key。不要把本机凭据脚本路径、变量值、认证头、服务错误正文或带 Key 的命令写进仓库、文档和诊断输出。Key 只在必要进程环境或内存保留，结束后清理；环境变量读取说明见根目录 README。

缺少 Key 时完成无需凭据的工作，将真实联调标为未验证；缺少模型/GPU时同样处理，禁止用 CPU、缓存命中或模拟日志声称 Vulkan 通过。用户授权 Agent 下载指定官方模型只是准备本机资产，不意味着应用获准新增自动下载功能。

## 验证与报告

按改动内容和风险选择必要检查，[开发指南](../development.md#构建与测试)提供可用命令，不作为提交门禁。提交或 amend 本身不要求运行锁定还原、构建、测试或发行检查；不为提交自动重跑全量验证。仅文档修改可检查链接、路径、术语、过期行为和证据一致性。真实付费请求及模型推理仍以用户授权和实际验证需要为限。

| 变更 | 重点验证 |
| --- | --- |
| 媒体/分片/时码 | 纯逻辑边界、实际 FFmpeg、Unicode/空格路径、二进制管道、进程树取消 |
| HTTP/参数 | fake `HttpMessageHandler`，请求体、认证缺失、错误分类、限次退避、取消及脱敏 |
| 翻译/提示词/缓存 | ID与时间不变、异常/部分结果、上下文、缓存隔离、定向重翻及原文不能冒充译文 |
| 本地引擎/native | 参数/身份/证据判断测试；影响实际推理时需真实 Vulkan、生成、EOS、取消和释放证据 |
| 页面/状态 | 桌面命令、导航与任务保持、配置快照、错误状态、XAML 渲染；原生人工项目另列 |
| 依赖/发行 | locked restore、资产/哈希/许可、仅 win-x64 原生库、包内运行时与正常退出 |

不同证据不能互换：测试总数不能证明真实 API；headless 截图不能证明原生拖放或高 DPI；发现 GPU、加载模型或缓存复跑不能证明新生成的 GPU offload；本机启动 self-contained 包不能证明独立无 SDK 机器验收。

交付报告包含：

1. 已实现行为、关键文件和影响。
2. 实际检查命令、结果；未执行项目及原因。
3. ElevenLabs、兼容 API、DeepSeek、Hy-MT2 Vulkan 的本轮状态，区分新增调用、历史结果、模拟和缓存。
4. 剩余限制/阻塞、脱敏证据和复现方式；说明 Windows x64 原生/GUI 人工验收是否进行。
5. 必要的下一步最小工作项，不自动扩展为新的产品功能。

无法运行验证时如实说明，不编造通过；可继续完成独立且已授权的部分。跨系统在 WSL 修改 Windows 项目时不构建，只做静态检查；正常 Windows 原生环境按上述命令验证。不需要替用户常驻启动开发服务器。

## 仓库、依赖与提交

- 仓库只保存正式源码、可维护测试、产品/工程文档、可复用工具、必要资源和许可。截图、TRX、日志、媒体、缓存、发行包及 GGUF 放忽略目录或仓库外。
- 不恢复旧 Spike 工程、日期绑定的运行脚本或整份聊天记录。确有验证需要时优先用正式引擎、测试和窗口；临时探测资产与代码分开，不能成为生产依赖。
- 依赖以项目文件、`global.json` 和锁文件为准。修改版本先核验对应官方 API/native 兼容性，更新锁文件和许可；不能关闭审计或警告来掩盖问题。
- 自有代码与文档使用根目录 [MIT 许可证](../../LICENSE)，发行包保留 `LICENSE`；第三方保留原许可、版权及声明，不将项目 MIT 套用到模型或依赖。新增或变更依赖按实际分发内容核对许可及源码提供义务，修改项目许可证须用户批准并更新决策。
- 模型与媒体可能包含必要资产或付费结果，清理前确认用途；递归移动/删除前核对绝对路径边界，不能清空未知缓存。
- 文档保持职责单一：行为放产品/UI，结构放架构，原因放决策，结果放状态，命令放开发指南。更新索引和失效引用，不复制相同规则到多处。
- 提交仅包含一个逻辑功能点。采用 Conventional Commits，描述使用中文，例如 `fix: 保留设置变更前的字幕导出`；用户未要求创建提交时不替用户提交或推送。

## 后续 Agent 交接

交接必须足够让新 Agent 不重启已完成阶段：列出本次目标及已批准范围、当前实现与改动入口、执行过的验证、尚未验证事项、必要资源的安全获取方式和下一步。长期信息落到对应文档；原始运行产物保留在忽略目录/外部归档。

当前开始点见[验证状态](status.md)。不要把“技术路线已验证”写成“完整产品已验收”，也不要将本机已安装 skill、FFmpeg、模型或 GPU 推断为所有开发环境都有。
