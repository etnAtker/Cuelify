# UI、交互与文案规约

本文件固化用户确认的界面方向和文案整改要求。适用于页面、按钮、标签、空状态、进度、错误、日志入口和高级设置；修改前同时阅读[桌面架构](architecture.md#桌面状态与配置归属)。

## 界面结构

- 单个 Avalonia 原生窗口，左侧约 80px 的图标导航配简短标签：工作台、日志，底部设置。正文完整显示选中页面，不恢复“左侧长期配置、右侧结果”的主布局。
- 设置与工作流分开。密钥、服务地址、模型路径、连接测试、提示词和高级参数属于设置页；运行记录和请求预览属于日志页。
- 工作台固定三步：选择文件 → 翻译选项 → 生成字幕。第一步的下一步先检查主密码解锁与 ElevenLabs 密钥，再实际检查媒体；第二步显示本次语言、引擎和配置入口；第三步显示进度、原译文、重翻和导出。
- 第二步只设置一次源语言与目标语言。源语言下拉显示中文名称，统一用于语音识别提示和翻译；自动识别时不发送 ASR 语言提示。新任务默认语言集中在设置的常规页，语音识别与翻译服务页不再重复编辑源语言。
- 日志支持单选、Ctrl/Shift 多选、全选、按钮/右键复制及 Ctrl+C；按显示顺序复制完整条目（含多行调用栈），相同文字的条目按所选行区分。
- 按阶段突出一个主要动作：下一步、开始处理、导出 SRT。取消、继续处理和其他动作按真实状态出现，不把所有命令一直堆在页面底部。
- 设置分为语音识别、翻译服务、提示词、常规；高级参数折叠。工作台的设置入口跳到对应分类，返回时保留文件、步骤和本次选项。
- 处理中允许切页查看日志和设置，锁定文件、步骤和相关参数；不因切页取消、清空或重建作业。已完成任务保留原配置，设置保存作用于新的处理。

## Avalonia 与视觉设计

沿用 FluentTheme、CommunityToolkit.Mvvm 和编译绑定。共享颜色/字体/间距在 `Design/Tokens.axaml`，控件样式在 `Controls.axaml`，矢量图标在 `Icons.axaml`。不为新页面另建不一致的调色板、字体或图标来源。

当前正文 14、标题 24，优先 Windows 系统字体及中文回退，间距采用现有 4/8 倍数节奏。使用语义颜色区分主操作、次要内容和错误，强调色有明确用途；避免营销页式大标题、装饰渐变、过多卡片和网页动效。

按浅色 1240×860、深色 900×640 检查当前布局；长内容可滚动，步骤和主操作应可见，字段不可因最小窗口而被遮挡。字幕表保持原文/译文列对齐，使用现有 ListBox 虚拟化，不一次创建所有行的可视控件。

控件应有清晰名称、键盘可达与可见焦点；不只靠颜色表达状态。图标保留标签/可访问名称，字段说明与错误就近呈现。动画短暂且有用途，遵守减少动画设置。高 DPI、键盘、文件对话框与拖放需要原生人工检查，不能由截图代替。

界面改动应使用可用的 Avalonia 专项和 UI 设计 skill；先读相关指南，再按当前版本核验 API。此前采用的来源为 [Avalonia development](https://github.com/wieslawsoltes/development-plugin-for-avalonia)与 [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)，详情见 D005。skill 是辅助资料，不是升级 Avalonia、引入 ReactiveUI/Zafiro 或网页技术栈的授权；即使本机没有安装这些 skill，本文件仍应可独立指导开发。

## 产品语言

**界面用正常软件的语言描述用户正在做的事。开发规约、实现细节和验收措辞不直接进入日常界面。**

1. 按钮写动作，标签写对象，辅助说明写必要影响，状态写实际进展，错误写具体问题和下一步。
2. 中文自然、简短、一致，不使用无意义宣传、缩写、训诫或“禁止/必须”等工程口号。不要为了说明设计正确而写防御性声明。
3. 日常界面使用字幕序号、时间、原文、译文；内部 cue ID、异常类型、调用栈、模块路径和 GPU 原始证据放诊断日志。
4. 技术字段仅在用户需要作出配置选择时保留，例如“温度（temperature）”“自定义请求参数（JSON）”“GPU 卸载层数”。不能一概抹掉所有技术词，也不能直接照搬 API 字段当主标签。
5. 数值范围由控件和校验处理，必要时给范围说明；输入实际违规时才说明具体原因，不把所有安全/验收规则提前挂在标签上。
6. 音频上传、云端发送原文、可能计费、是否保存密钥、覆盖文件等有实际后果的信息应保留，并放在相关操作附近简洁说明。
7. 说明随引擎与状态变化。例如本地系统提示词说明不应出现在云端，默认 DeepSeek 不应显示“本地模型尚未加载”。

| 避免的文案 | 推荐表达或处理 |
| --- | --- |
| 从一个本地媒体文件生成可复用的字幕 | 识别并翻译音视频字幕；或直接显示当前任务标题 |
| 高级 JSON · 禁止 Key / headers | 自定义请求参数（JSON）；校验失败时说明具体字段 |
| GPU layers · 必须大于 0 | GPU 卸载层数；用数值范围限制 |
| 进程内 Vulkan；无 GPU 时明确报错 | 模型说明只写需要支持 Vulkan 的显卡；诊断详情进入日志 |
| 本地批次与并发固定为 1 | 无需常驻提示用户不可调整的内部规则 |
| 开始 / 从缓存恢复 | 开始处理；实际可以继续时显示继续处理 |
| 重翻选中条 | 重新翻译所选字幕 |
| ID / 原时码 | 序号 / 时间 |
| 测试连接 / 本地 GPU 加载 | 云端：测试连接；本地：测试本地翻译 |
| 待翻译 / 失败 | 分别显示等待翻译、翻译中、翻译失败、已取消 |
| InvalidOperationException | 请填写有效的对应服务 API 密钥，或给出实际配置错误 |
| 失败 · 可从缓存恢复 | 按真实原因和可恢复状态显示，不对所有异常承诺恢复 |

表中的例子约束表达方式，不要求把所有推荐说明常驻展示。没有用户需要了解的额外信息时，省略辅助提示更合适。

## 状态与错误必须准确

- 等待不等于失败，识别成功不等于翻译成功。识别完成即可显示原文，译文按校验后的批次逐步出现；不显示虚构的完成比例或示例结果。
- 切换服务或修改测试相关配置/Key 后重置连接测试状态，不能沿用另一个配置的成功结论。服务测试不覆盖已完成媒体任务的状态和导出资格。
- 取消中、已取消、部分失败、完成分别处理；已完成的有效译文保留，未完成行按实际状态显示。禁止原文静默填补失败译文。
- 缺少 Key 给出对应服务的输入建议并进入相关设置；401、403、429、5xx、网络故障、参数错误分别映射原因，不统一让用户同时检查所有可能性。
- 文件无效留在选择文件步骤；缺少 ffprobe 等工具才指向路径配置。显存不足、模型身份错误、GPU 不可用等给用户可执行建议，技术证据记录到日志。
- 主错误区不直接展示 exception.ToString。复用 `UserErrorMessages` 和安全错误分类，过滤凭据；原始服务错误正文与认证头即使在日志中也不得记录。
- 只有具备继续条件才提供继续处理。完整译文缺失时禁用完整 SRT 导出，不能只改按钮文字而忽略命令状态。

## 每次界面改动的自查

检查用户是否能知道当前步骤、下一步动作及失败后的处理方式；每条提示是否有真实用途、是否与实际状态一致；是否误把开发或验收要求写给用户。覆盖空状态、等待、运行、取消、部分失败、完成和设置变更，检查浅深色、最小窗口、长中文及字幕列对齐。

交互回归测试关注命令与真实状态转换，不能只验证字符串被替换。截图须标明 headless/测试替身，不能当作真实 ASR、云端翻译或 GPU 生成证据。

## 主密码与凭证交互

密钥配置区域显示未设置、已锁定、已解锁三种状态，分别提供设置主密码、解锁、锁定快捷操作。解锁后可编辑密钥并独立保存，非敏感设置仍使用保存设置。主密码不限制长度或字符构成，只校验必填及创建/更换时的两次输入一致性；支持粘贴和显示密码，取消保留原页面与任务选项。忘记密码的后果在创建时简短说明，重置前确认清除全部密钥。

禁用下一步、开始/继续处理和云端重翻时就近显示原因与设置/解锁入口，不只显示灰色按钮；步骤标题不能绕过检查。缺少多个服务密钥时一起列出，切换引擎立即更新所需凭证，本地不要求云端翻译密钥。连接测试不作为流程门槛，解锁成功不等于服务认证成功。导出和已有结果不因锁定失效。

兼容服务地址变化时提示确认密钥用于新地址，确认操作说明密钥会发送到该地址。处理中禁用凭证编辑、锁定、更换和重置；加密保存失败保留输入，不声称已保存。常规页提供更换主密码和重置凭证，不新增导航分类。
